# AI 悬浮桌面宠物 · 三期需求头脑风暴与产品方案

> 日期：2026-08-25
> 状态：高保真原型评审稿 v3
> 本文记录本轮已确认的产品决策，并作为三期详细实施计划的输入。界面示例位于同目录 `界面示例.html`。

## 1. 本期目标

三期把原“配置中心”升级为可长期使用的正式桌面工作台，围绕三项一级能力展开：

1. 提示词管理工具：统一管理提示词和常用命令。
2. 日程管理：整合每日任务看板、月历与现有提醒管理。
3. 设置：在同一完整页面管理通用配置和大模型配置。

桌宠的陪伴与对话能力继续保留。右键桌宠打开工作台，双击桌宠仍打开对话面板，单击动作与提醒表现不变。

## 2. 已确认的关键决策

| 主题 | 决策 |
|---|---|
| 窗口形态 | 自定义无边框正式应用窗，支持任务栏、最小化、最大化/还原和边缘缩放 |
| 推荐尺寸 | 默认 1180×760，最小 960×640 |
| 顶部导航 | 仅“提示词管理工具 / 日程管理 / 设置”，点击直接切换主内容区 |
| 设置入口 | 不使用下拉菜单、弹窗、二级页签或子栏目 |
| 项目空间 | 仅一级分类，支持增删改名和排序 |
| 内容模型 | 提示词和命令使用统一卡片模型，以类型标签区分 |
| 卡片布局 | 有封面时显示大卡片；无封面时显示紧凑卡片 |
| 卡片操作 | 单击打开右侧详情抽屉；显式按钮复制；双击正文可快速复制 |
| 命令安全 | 只存储和复制，永不执行 |
| 封面来源 | 本地选择或拖拽上传，复制到应用数据目录；暂不支持网络 URL |
| 每日任务 | 长期待办 / 今日事项两列；区间任务自动映射，当日偶发事项可手动创建，完成后从活跃视图移除 |
| 月历范围 | 展示长期任务日期区间、当日任务和定点提醒；不展示周期/使用时长提醒 |
| 提醒关联 | 任务可选关联提醒；删除任务时决定是否同步删除关联提醒 |
| 日程内部导航 | 今日看板默认；工具栏切换日程表、提醒管理，并可返回今日看板 |

## 3. 产品信息架构

```text
正式应用窗口
├─ 提示词管理工具
│  ├─ 一级项目空间
│  ├─ 提示词/命令卡片库
│  └─ 内容详情与编辑抽屉
├─ 日程管理
│  ├─ 长期待办 / 今日事项两列看板（默认）
│  ├─ 月历
│  └─ 提醒管理
└─ 设置
   ├─ 通用设置
   ├─ 大模型配置
   └─ 版本、数据目录与退出入口
```

顶部导航只表达三个一级能力。月历、提醒等二级视图只在“日程管理”页面内部切换；设置内容在一个页面中自然纵向排列。

## 4. 正式应用窗口

### 4.1 行为

- 右键桌宠时创建或恢复工作台窗口；已存在时只恢复、聚焦，不重复创建。
- 默认打开用户上次停留的一级页面，首次打开进入提示词管理工具。
- 关闭工作台窗口不退出桌宠；“退出宠物”仍是完全退出应用的唯一显式入口。
- 窗口显示在任务栏，支持最小化、最大化/还原和窗口边缘缩放。
- 默认 1180×760；最小 960×640，窗口缩小时允许纵向滚动，保证看板和表单仍然可读、可操作。
- 位置和大小可持久化；显示器变化后按现有多屏边界策略修正到可见区域。

### 4.2 视觉

- 沿用“萤光织界”：夜幕、钢蓝、萤青、薄荷、晶金、羽粉、月白。
- 自定义标题栏使用深色钢蓝；工作区使用月白底面，不再保留配置中心“透明窗口中单张卡片”的形态。
- 胸前晶体作为应用标识，羽饰与几何纹理作为低密度装饰。
- 禁止使用已移除的 `diamond-mark` 元素；继续使用现有 `diamond-tile` 低对比纹理。
- 卡片、输入框、按钮和动效继续遵守现有圆角与 150ms 反馈标准。
- 整体字号在二期视觉基线上提升约 2px：正文以 14px 为基线，导航、标题、表单与日历信息同步放大；空间不足时优先滚动，不以压缩字号换取密度。

## 5. 提示词管理工具

### 5.1 一级项目空间

初始示例为“常用命令、海报制作、AI 绘图、文稿写作”。用户可以：

- 新建、重命名、拖动排序空间。
- 删除空空间。
- 删除非空空间时选择“迁移到其他空间”或“一并删除内容”；默认推荐迁移。
- 折叠左侧栏以扩大卡片区，但不引入二级文件夹。

### 5.2 统一内容模型

提示词和命令共享标题、正文、空间、封面、置顶、收藏、时间戳等字段。类型只用于标签和筛选，不形成两套 CRUD。

右侧工具栏提供：

- 标题与正文全文搜索。
- 全部 / 提示词 / 命令筛选。
- 置顶优先、最近更新、标题排序。
- 新建内容。

### 5.3 卡片与详情

- 有封面：封面图、类型、标题、正文前两至三行、更新时间、收藏和复制。
- 无封面：缩短高度，突出标题、正文预览或命令代码块。
- 单击卡片打开右侧详情抽屉，不直接复制。
- 卡片复制按钮和抽屉“复制全文”按钮负责明确复制；双击正文是补充快捷方式。
- 详情抽屉可编辑全部字段、上传/替换/删除封面、移动空间、置顶、收藏和删除。
- 命令内容始终只作为文本复制，不添加执行入口。

### 5.4 封面管理

- 允许选择本地 PNG/JPEG/WebP，或拖拽文件到封面区域。
- 主进程验证文件类型和大小后，复制到 `userData/prompt-covers/`，用内容 ID 命名。
- 保存相对路径或受控资源 ID，不长期依赖用户原文件路径。
- 删除/替换封面时清理旧副本；缺失或损坏时显示主题占位图。
- 首期不支持网络 URL，避免远程失效、隐私泄露和加载失败。

## 6. 日程管理

### 6.1 今日看板

- 默认展示“长期待办 / 今日事项”两列，不提供已完成栏目。
- 长期待办用于持续性事务，采用酒店入住式区间选择器，在同一月历中依次选择开始日期和结束日期，区间首尾都包含。
- 当所选日期位于长期待办区间内时，同一任务自动映射到今日事项，不复制数据；超出区间后自动退出今日事项。
- 今日事项允许手动新建只属于所选日期的偶发任务，并用来源标识与区间映射任务区分。
- 完成操作仍保留；完成后任务直接从两列看板和日历移除，不进入已完成列表。
- 顶部支持前后日期、回到今天、任务搜索、新增长期待办、日程表和提醒管理。
- 任务卡显示标题、时间、优先级、提醒状态、日期范围和来源。
- 新建/编辑字段：任务类型、标题、日期区间或单日、时间、优先级、备注、到点提醒。

### 6.2 月历

- 月视图显示长期任务日期区间、单日任务与定点提醒。
- 区间任务在每天的日期格中以连续色带呈现，开始和结束使用圆角端点；日期详情明确标注“区间任务”或“当日任务”。
- 点击日期后展示当天内容，允许快速新建任务。
- 周期提醒和使用时长提醒不铺入月历，避免重复条目污染视图。
- 页面明确提供“返回今日看板”。

### 6.3 提醒管理

- 保留现有定点、周期与使用时长提醒的 CRUD、启停和触发逻辑。
- 仅重新布局和统一视觉，不改变旧提醒语义。
- 任务启用“到点提醒”时创建关联定点提醒，并保存 `reminderId`。
- 删除关联任务时弹出安全选择：仅删除任务，或同时删除关联提醒。
- 删除提醒时如存在关联任务，只移除任务的 `reminderId`，不删除任务。

## 7. 设置页

点击顶部“设置”后直接切换完整设置页。页面不含子栏目导航，内容按视觉分组纵向排列。

### 7.1 通用设置

- 始终置顶。
- 开机启动。
- 提醒音量。
- 减少动态效果。
- 数据存储位置与“打开目录”。

布尔开关和音量即时生效，并显示简短保存状态。

### 7.2 大模型配置

- API Key、接口地址、模型、人设。
- 保存大模型配置。
- 清空对话历史。

API Key 继续遵守现有安全红线：只由主进程存储和使用，渲染层只获得“已配置/未配置”状态，绝不回显真实值。

### 7.3 应用级操作

页面底部显示版本信息、数据目录入口和弱化的“退出宠物”。危险操作使用二次确认。

## 8. 建议数据模型

```jsonc
{
  "schemaVersion": 3,
  "spaces": [
    { "id": "space-commands", "name": "常用命令", "order": 0, "createdAt": 1787625600000 }
  ],
  "entries": [
    {
      "id": "entry-1",
      "spaceId": "space-commands",
      "type": "command",
      "title": "启动本地项目",
      "content": "npm install\nnpm run dev",
      "coverId": null,
      "pinned": true,
      "favorite": false,
      "createdAt": 1787625600000,
      "updatedAt": 1787625600000
    }
  ],
  "tasks": [
    {
      "id": "task-1",
      "kind": "range",
      "title": "确认三期界面方案",
      "startDate": "2026-08-24",
      "endDate": "2026-08-27",
      "time": "10:30",
      "priority": "high",
      "notes": "整理评审意见",
      "reminderId": "reminder-1",
      "completed": false,
      "createdAt": 1787625600000,
      "updatedAt": 1787625600000
    }
  ],
  "reminders": [],
  "settings": {
    "workspaceWindow": { "bounds": null, "maximized": false, "lastPage": "prompts" },
    "alwaysOnTop": true,
    "launchAtLogin": false,
    "volume": 0.8,
    "reducedMotion": false,
    "chat": {}
  }
}
```

约束：

- `type` 仅允许 `prompt` 或 `command`。
- `kind` 仅允许 `range` 或 `today`；`range` 使用 `startDate/endDate`，`today` 使用 `date`。
- 长期任务是否进入今日事项由所选日期与区间自动计算，不保存第二份任务或可拖动状态。
- `completed=true` 的任务不出现在活跃看板与日历；本期原型不提供已完成栏目。
- `priority` 仅允许 `low`、`normal`、`high`。
- 日期使用本地日历日期 `YYYY-MM-DD`，避免 UTC 转换导致跨日。
- 关联使用 ID，不嵌套复制提醒对象。

## 9. 旧数据迁移

1. 检查 `schemaVersion`；低于 3 时启动一次性迁移。
2. 迁移前把旧 `commands`、`reminders`、`settings` 写入带时间戳的备份键或备份文件。
3. 创建默认“常用命令”空间。
4. 每条旧命令转换为 `entry`：标题、正文和 `pinned` 原样保留，类型设为 `command`。
5. 旧提醒数组原样保留，不自动转换为任务。
6. 保留旧大模型配置，新增设置字段使用安全默认值。
7. 全部校验通过后才写入 `schemaVersion: 3`；失败时不删除旧字段，并提示可恢复。
8. 至少保留一个版本周期的兼容读取，再考虑清理旧 `commands` 字段。

## 10. 建议工程边界

当前 `renderer.js` 已同时承担宠物、聊天、命令、提醒和配置逻辑。三期页面量明显增加，建议在不引入前端框架的前提下拆分：

```text
main.js                       窗口生命周期与 IPC 注册
main/
├─ workspace-window.js       正式工作台窗口、尺寸与多屏恢复
├─ storage.js                schema v3、迁移、备份和校验
├─ prompt-covers.js          封面导入、读取与清理
└─ schedule-service.js       任务与提醒关联规则
renderer.js                   桌宠窗口入口与对话逻辑
workspace.html                正式工作台结构
workspace.css                 工作台视觉与响应式布局
workspace.js                  顶部页面路由与共享状态
renderer/
├─ prompts.js                空间、内容卡片和详情抽屉
├─ schedule.js               看板、月历、提醒视图
└─ settings.js               通用与大模型设置
```

这些模块只通过明确 IPC 与数据服务通信。继续保持 `contextIsolation: true`、`nodeIntegration: false`、渲染用户文本使用 `textContent`。

## 11. 异常与边界处理

- 窗口恢复坐标不在任一显示器可见区时，回到鼠标所在屏幕中央。
- 小于最小尺寸时由 BrowserWindow 阻止继续缩小；卡片网格在可用宽度下降为两列或一列。
- 空间重名时阻止保存并聚焦名称输入框。
- 非空空间删除必须明确内容去向。
- 封面格式不合法、过大或复制失败时不保存路径，并展示具体错误。
- 数据损坏时读取备份或安全默认值，不覆盖损坏源文件。
- 任务和提醒关联操作在一次主进程事务中完成，避免只成功一半。
- 日期区间缺少开始或结束日期、结束早于开始时阻止保存并聚焦区间选择器。
- 大模型保存失败沿用现有友好错误归一；未配置 Key 不影响其他管理功能。

## 12. 验收标准

### 12.1 工作台窗口

- 右键桌宠打开正式窗口，桌宠原位不动。
- 窗口可最小化、最大化、还原和边缘缩放，并显示在任务栏。
- 关闭工作台后桌宠继续运行；重新打开恢复上次页面。
- 960×640、多屏和不同缩放环境下主要功能可用。

### 12.2 提示词管理

- 空间可增删改名和排序，非空删除不会误丢数据。
- 提示词和命令可增删改、搜索、筛选、排序、置顶、收藏和复制。
- 有图/无图卡片正确切换；封面重启后仍可显示。
- 旧命令完整迁移到默认空间，命令不能被执行。

### 12.3 日程管理

- 长期任务在区间首尾两日均自动进入今日事项，区间外自动退出且仍保留在长期待办。
- 当日偶发任务只显示在指定日期；完成后从活跃看板和日历移除。
- 月历连续显示区间任务，并在日期详情中反馈任务来源。
- 日历只显示任务和定点提醒。
- 任务提醒关联与删除分支符合确认规则。
- 旧提醒仍可增删改、启停和正常触发。

### 12.4 设置与安全

- 顶部导航仅有三个入口，均一键切换完整页面。
- 通用设置和大模型配置位于同一设置页。
- API Key 不进入渲染层、不进安装包、不输出到日志。
- 用户文本不以 `innerHTML` 拼接，封面读取路径受主进程约束。

## 13. 建议实施顺序

三期应继续遵守“一次一个里程碑、一步一验”：

1. P3-M0：规范、schema v3 与迁移测试。
2. P3-M1：正式工作台窗口与三项顶部导航。
3. P3-M2：项目空间和统一内容模型。
4. P3-M3：卡片、详情抽屉与封面管理。
5. P3-M4：长期待办 / 今日事项两列看板与日期区间映射。
6. P3-M5：月历、提醒管理和任务提醒关联。
7. P3-M6：完整设置页与旧大模型配置迁移。
8. P3-M7：响应式、多屏、打包与总验收。

详细任务拆解应在本评审稿获批后单独编写，实施前先同步修订项目的需求规范、技术规范、设计规范、开发步骤和开发日志。

## 14. 本轮不做

- 二级或多级项目空间。
- 提示词变量模板、批量运行、版本历史和云同步。
- 网络封面 URL。
- 表格/画廊双模式。
- 命令执行、文件执行或 Agent 工具调用。
- 周/日时间轴、复杂重复日程和错过补偿。
- 修改正式应用代码或正式数据；本轮产物仅供产品与视觉评审。

## 15. 高保真原型交付说明

本目录的 `界面示例.html` 已从静态方案演示升级为实施前高保真窗口原型，覆盖空间与内容 CRUD、长期待办与今日事项两列看板、酒店式日期区间选择、区间自动映射、月历连续色带、三类提醒管理、完整设置表单、危险操作确认、字段校验、空状态和 960×640 最小尺寸适配。

根据本轮评审决定，原型数据不持久化：新增、编辑、删除、完成和设置修改只在当前页面有效，刷新后恢复预置案例。真实 Electron 窗口控制、存储、IPC、系统提醒和模型连接仍留在正式实施阶段，不以浏览器模拟结果替代工程验收。
