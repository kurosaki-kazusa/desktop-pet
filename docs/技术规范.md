## 1. 技术选型（已定）

| 项 | 选择 | 理由 |
|---|---|---|
| 运行框架 | **Electron**（最新稳定版） | 透明置顶窗口原生支持，AI 生成代码质量最高 |
| 项目结构 | **最小化三文件**：`package.json` + `main.js` + `index.html` | 简单清晰，维护成本低（Q1A） |
| 渲染层 | **原生 HTML/CSS/JS**，零依赖零构建 | 实现最简，代码直观（Q2A） |
| 数据持久化 | **electron-store** | 一行代码完成 JSON 读写（Q3A） |
| 提醒呈现 | **应用内悬浮气泡 + 提示音**，不用系统通知 | 效果直观可控（Q4A） |
| 宠物素材 | **透明 PNG 逐帧动画**（v2.6：`assets/pet-actions/`，由 WebP 精灵图切分） | 角色素材真实可控，透明背景可直接用于悬浮窗 |
| 提示音 | **WebAudio 合成双音提示音 + 使用时长语音**（`assets/audio.wav`） | 普通提醒轻提示，使用电脑 1 小时提醒播放语音 |

**依赖清单**：运行时 `electron-store`；开发 `electron`、`electron-builder`（打包）

## 2.5 应用打包（v1.5，v1.0.1 纯净版更新）

- **打包器**：electron-builder 26，NSIS 安装包（`dist\AI桌宠 Setup 1.0.1.exe`，oneClick 关闭、可选安装目录、创建桌面快捷方式）
- **命令**：`npm run dist`（普通打包）/ `npm run make-icon`（重新生成图标源图）；本机推荐**一键打包**：双击根目录 `一键打包.bat` 或 `npm run dist:clean`（内部执行 `scripts/dist-temp.ps1`，见下）
- **纯净性**：`files` 白名单包含核心代码文件与 `assets/**/*` 静态素材，并排除头像原始截图 `assets/ScreenShot_2026-08-24_100223_551.png`；用户数据（常用命令/提醒/会话历史）存于 electron-store 默认 userData（开发模式 `%APPDATA%\ai-desktop-pet`，安装版 `%APPDATA%\AI桌宠`），**从不进入安装包**——安装包天然纯净；`.env`（API Key）既被 .gitignore 排除也被 files 白名单排除，绝不进包/进仓库
- **图标链路**：`scripts/make-icon.js` 将 `assets/pet-actions/action-04/frame-03.png` 等比放大并居中到 512×512 透明画布 → `assets/icon.png` → electron-builder 打包时自动转 `icon.ico` 嵌入 exe
- **网络镜像**（国内网络必需）：`electronDownload.mirror` 指向 npmmirror 的 electron 镜像；打包工具包（winCodeSign/nsis/nsis-resources/7zip）通过 `ELECTRON_BUILDER_BINARIES_MIRROR` 环境变量加速，首次下载后缓存于 `%LOCALAPPDATA%\electron-builder\Cache`
- **输出目录锁坑（v1.0.1 遇坑）**：项目位于 `D:\Documents`（被同步盘/安全软件监控）时，打包在解压 electron zip 后 unlink/rename asar 文件会持续报 EBUSY/EPERM（句柄被外部进程持有，重试无效）。解法：输出目录改到系统 TEMP（`--config.directories.output=%TEMP%\ai-pet-dist`），打包成功后复制安装包回 dist\；已固化为 `scripts/dist-temp.ps1`
- **一键打包脚本（v2.2）**：`scripts/dist-temp.ps1` 四步流水线——清理 TEMP 残留 → electron-builder 打包 → **纯净性校验**（asar list 核对：顶层只允许 7 项白名单 `package.json/main.js/preload.js/renderer.js/index.html/styles.css/chat.js`，node_modules 为生产依赖自动跳过，个人配置/用户数据存于 %APPDATA% 永不进包）→ 复制安装包回 dist\（仅保留最新）；入口：双击 `一键打包.bat` / `npm run dist:clean`。**编码坑**：ps1 必须带 UTF-8 BOM，否则 Windows PowerShell 5.1 按 GBK 解码中文字符串会破坏语法（报 exit 未识别等怪错）

## 3. 关键窗口配置（主进程）

```js
const win = new BrowserWindow({
  width: 560, height: 560,          // 覆盖宠物+气泡展开区域（放大版）
  frame: false,                      // 无边框
  transparent: true,                 // 真 alpha 透明
  alwaysOnTop: true,                 // 置顶
  resizable: false,
  skipTaskbar: true,                 // 不占任务栏
  webPreferences: { preload: ..., contextIsolation: true }
});
```

- **点击穿透策略**：窗口整体 `setIgnoreMouseEvents(true, { forward: true })`，渲染层在鼠标进入宠物/气泡 DOM 区域时通过 IPC 动态切换回可交互模式，离开后恢复穿透 —— 保证宠物不遮挡桌面操作
- **配置中心独立窗口（v1.4，v2.1 入口改为右键）**：右键宠物时通过 `window:set-config-open(true)` 让主进程创建**第二个 BrowserWindow**（700×680，居中于鼠标所在屏，类似应用设置窗口），宠物窗口保持原位不动；配置窗口以 `?mode=config` 加载同一 index.html，渲染层检测后隐藏宠物/气泡/通知、居中铺开面板；✕/Esc 关闭（`window:set-config-open(false)`）。配置窗口的增删改通过 `data:changed` 广播给宠物窗口实时同步（排除发起者自身）
- **配置中心拖动（v1.6，v2.4 加 rAF 节流）**：拖动机制泛化为**两窗口共用**——`window:drag-start` 按 `BrowserWindow.fromWebContents(e.sender)` 识别来源窗口，从对应位置账本（宠物 `lastLogicalPos`/配置 `cfgPos`）取锚点；`window:drag-to` 按 `dragWin` 尺寸与保留可见量（宠物 48/64px、配置 160/120px）约束并集边界后 setBounds。**渲染层 mousemove 加 rAF 节流**（鼠标事件 125-1000Hz，一帧最多发一次 drag-to，setBounds 频率压到 60Hz 内），endDrag 统一收尾（cancelAnimationFrame 丢弃未发帧）。配置窗口拖完不落盘（下次打开仍居中）；渲染层按住面板头部（排除 button/.tabs）发拖动信号，含 mouseup 丢失三重兜底
- **置顶保活（v2.4）**：Windows TOPMOST 无绝对优先级（后来激活的置顶窗口会盖住桌宠）→ 窗口创建后提升至 `setAlwaysOnTop(true, 'screen-saver')`（高于默认 floating，压过绝大多数置顶窗口）+ 每 5 秒 `moveTop()` 保活（只调 Z 序、不抢焦点、无闪烁）；配置中心 panel-footer 新增「始终置顶」勾选（settings.alwaysOnTop，默认 true），关闭时 `applyTop(false)` 降级普通窗口并停止保活——把与用户主动置顶应用（视频小窗等）的冲突选择权交还用户；cfgWin 同级保活；IPC `window:set-always-on-top`
- **交互面板（v2.0 取代复制看板，v2.1 入口改为双击，v2.3 接入大模型，v2.8 替换头像，v2.9 主题升级）**：气泡由“复制看板”改为**对话交互面板**——`#chat-log` 消息流 + `#chat-input` 输入框 + 发送按钮；首次打开自动追加默认问候语（CHAT_GREETING），用户消息右对齐深青气泡、宠物回复左对齐月白/薄荷气泡（带 `assets/chat-avatar.png` 透明角色头像）；v2.9 通过 CSS 引用 `assets/ui-theme/firefly/` 的夜幕背景、羽饰、晶体、纹理与粒子，`diamond-mark` 不得引用；**v2.3 起发送消息经 `chat:send` IPC 交给主进程 chat.js 引擎，流式 chunk 经 `chat:chunk` 逐字渲染**（deepseek-reasoner 的 reasoning 内容进入可折叠思考区，正文带打字光标，完成/出错经 `chat:done`/`chat:error` 收尾，面板关闭/重发时 `chat:abort` 中止未完成请求）；对话记录在窗口存活期间保留，关闭面板不重置；打开面板时自动 focus 输入框
- **命令置顶（v2.0）**：quick 字段迁移为 pinned——data:get-all 归一化时 `quick=true` 迁移为 `pinned=true` 并删除 quick 字段写盘；置顶无数量上限；渲染时置顶条目排最前（保持原有相对顺序），列表项右侧 checkbox 勾选即置顶；“退出宠物”按钮移入配置中心底部（panel-footer）
- **复制看板单行显示（v1.6，已随看板下线）**：bubble 模式列表项内容取 `content.split('\n')[0]` + `single-line` 样式（nowrap/ellipsis/max-height none），点击仍复制全文，悬停 title 显示完整内容
- **位置记忆（多屏适配）**：窗口坐标存入 electron-store，启动时经 `screen` 模块校验——位置必须落在某块显示器的 workArea 内（宠物主体至少 32px 可见），否则用 `getDisplayNearestPoint` 就近吸附到最近屏幕右下角（覆盖拔副屏/改分辨率场景）；拖动采用**绝对锚点方案**（drag-start/drag-to/drag-end 三通道，渲染层只发信号不传坐标，定位坐标一律由主进程 `screen.getCursorScreenPoint()` 采集——规避渲染层 e.screenX/Y 在混合 DPI 多屏下的失真），目标位置 = 当前鼠标 + 按下时偏移，无增量累加；锚点与落盘均基于主进程**自维护的逻辑位置账本**（拖动全程不读 `win.getPosition()`，切断混合 DPI 下 getPosition/setPosition 往返误差的闭环累积，消除“每次拖动向下漂移”）；拖动边界为**所有显示器的并集包围盒**（不按单屏 workArea 限制，避免窗口被“钉”在边界不跟随鼠标），仅保证宠物主体至少 48/64px 在屏幕并集内不拖丢，显示器插拔/变更时自动失效重算；每次 `setPosition` 后立即 `setSize(WIN_W, WIN_H)` 复位尺寸，并启用 `useContentSize: true`——规避 Windows 非 100% 缩放下 setPosition 附带隐形尺寸漂移导致 bottom 定位宠物“下沉”的远古 bug；**应用级强制 `force-device-scale-factor=1`**（窗口创建前设置，所有屏幕坐标统一为物理像素，副屏与主屏走同一坐标路径），拖动调用统一为 `setBounds({x,y,width,height})` 一次设定位置与尺寸；拖动中锁定点击穿透切换（防 mouseup 丢失导致状态卡死），mouseup 丢失时以 `(e.buttons & 1) === 0` 兜底结束，窗口失焦（blur）时强制结束拖动（防悬停漂移）；drag-end 即时落盘位置（Q15A）
- **preload 桥接**：渲染层不直接访问 Node API，所有数据读写/窗口控制通过 IPC（`contextBridge` 暴露受限接口），为二期扩展留出安全边界

## 4. 数据模型（electron-store）

```jsonc
{
  "reminders": [
    { "id": "r1", "type": "absolute", "time": "14:30", "text": "开会", "enabled": true },
    { "id": "r2", "type": "interval", "intervalMin": 60, "text": "已使用电脑1小时，起来活动", "enabled": true, "preset": "usage" }

  "commands": [
    { "id": "c1", "title": "清缓存", "content": "npm cache clean --force", "quick": true },

}
```

- 使用时长提醒以 `preset: "usage"` 标记，首次启动自动预置，用户可修改间隔；不再自动预置护眼提醒。启动迁移仅在固定 ID、类型、45 分钟和原文案全部匹配时删除旧版系统护眼预置，用户新建或改过的护眼提醒不受影响
- 使用时长计时 = 应用启动时刻起累计（Q7A）
- 命令字段（v1.2）：`quick`（boolean）标记是否显示在右键便捷菜单，**上限 5 条**；`content` 支持跨行长文本（上限 2000 字符）；旧数据无 `quick` 字段时在 `data:get-all` 中归一化为 `true`，超过 5 条按顺序保留前 5 条并写回
- **v3.0 起：旧 `commands` 表为兼容读取字段（P3-M0 迁移后不再写入），真实数据源为 `entries`（见 §4.5）；`data:get-all` 与 `command:*` IPC 对外形态不变，内部经 main/storage.js 映射辅助转换，渲染层零改动**

约束：

- `type` 仅允许 `prompt` / `command`；`defaultPage` 仅允许 `prompts` / `notes`
- `notes.spaceId` 可为空（未分类）；`kind` 仅允许 `range` / `today`——`range` 用 `startDate/endDate`，`today` 用 `date`
- `priority` 仅允许 `low` / `normal` / `high`；`completed=true` 的任务不出现在活跃看板与日历

- 关联使用 ID（`reminderId`），不嵌套复制提醒对象；任务与提醒的关联/解绑/删除分支在主进程事务中完成
- 旧表 `commands/reminders/settings` 保留一个版本周期后再清理

## 4.6 一次性迁移机制（main/storage.js，P3-M0）

- **触发**：main.js 启动时（窗口创建前）调用 `storage.migrate(store)`；`schemaVersion >= 3` 时幂等只补缺失默认字段，不重复迁移
- **流程**：备份 → 快照 → 转换 → 校验 → 落盘 → 写版本号：
  1. 备份旧 `commands/reminders/settings` 至 `backupSchemaV2`（带时间戳；即使迁移失败也保留）
  2. 转换：旧命令 → `entries`（标题/正文/pinned 原样，quick=true 视为 pinned，type=command，归入默认「常用命令」空间）；reminders 原样；settings 深合并补三期默认字段（旧值优先）
  3. `validateData` 全部通过（spaces 非空/id 唯一、entries 的 spaceId/type/字段合法、defaultPage 枚举等）才落盘；`schemaVersion` 最后写入作为完成标记
- **失败回滚**：按快照恢复迁移前原值（原本不存在的键删除）；**不写 schemaVersion、不删除旧 commands 字段**；主进程 console.error 提示可从 backupSchemaV2 恢复
- **模块设计**：纯 Node 模块零 Electron 依赖（store 只需 get/set/has/delete 接口），与 chat.js 同样可用系统 node 单测；`scripts/test-storage.js`（`npm run test:storage`）覆盖迁移成功/失败回滚/幂等/全新安装/旧命令映射辅助 7 项
- **过渡期映射辅助**：`commandsFromEntries`（entries → 旧命令 UI 形态，供 `data:get-all`）、`entryFromCommand`/`applyCommandToEntry`（command:add/update → entries，保留空间/封面/时间戳等三期字段）；P3-M2 提示词管理页上线后逐步切换为直接消费 entries

## 5. 提醒调度机制

- 主进程每 **10 秒**轮询一次（`setInterval`）：比对当前时间与定点提醒、累加周期提醒与使用时长计时
- 触发后通过 IPC 通知渲染层：切换提醒动画 → 播放提示音 → 弹出提醒气泡（展示 3-5 秒后自动收回或点击关闭）
- 不引入错过补偿逻辑（Q18A）

## 5.5 大模型会话后端（v2.3：chat.js，设计复刻 deepseek-harness）

> 原则：**不依赖、不改动** deepseek-harness（参考项目，.gitignore 排除，后续将删除）；只把 harness 会话设计中的精华要点复刻为桌宠的纯 Node 模块 `chat.js`（主进程内运行，零新增依赖——用 Node 内置 fetch + electron-store）。

**配置解析优先级（resolveConfig）**：进程环境变量（process.env，含 .env 注入） > 配置中心「大模型」页签保存值 > .env 文件 > 默认值。`.env` 在 main.js 启动时由 `loadEnvFrom` 按「项目根（开发）→ 安装目录 exe 旁（打包）→ userData」三处解析注入（仅读取不落盘，Key 不进渲染层、不进安装包）。**v2.5 配置文件机制**：打包版首次启动时 `seedEnvTemplate()` 在安装目录生成带注释的 `.env` 模板（DEEPSEEK_API_KEY/BASE_URL/MODEL/SYSTEM_PROMPT，编辑后重启生效；安装目录不可写时回落 userData，两处都在 loadChatEnv 读取范围内）；配置中心 hint 经 `data:get-all` 的 `envFile` 字段显示 .env 实际路径；dist-temp.ps1 在 dist\ 附 `.env.example` 说明文件。

| 复刻的设计要点 | 来源 | 落地方式 |
|---|---|---|
| **SSE 流式解析**（`data:` 行、`[DONE]` 终止、多行事件聚合） | harness llm-streaming | `parseSSEChunk` 行缓冲 + 事件聚合，分帧推送不丢字符 |
| **正文/思考分离**（reasoner 的 `reasoning_content` 独立通道） | harness llm-streaming | chunk 带 `kind` 标记（think/正文），渲染层思考区独立展示 |
| **防御式错误归一**（无 Key/超窗/限流/空回复映射为稳定错误码与友好文案） | harness defensive-patterns | `normalizeError` 按 HTTP 状态/错误码路由，文案含操作指引 |
| **空回复重试一次** | harness defensive-patterns | EMPTY_RESPONSE 自动重试一次，仍空则归错误提示 |
| **上下文自动压缩**（超窗时压缩历史而非直接丢历史） | harness compaction | 历史超出 `chat.maxTurns`（默认 12 轮）时用大模型生成摘要替换早期轮次，摘要+近期轮次入上下文 |
| **提示词结构化组装**（人设/当前时间/能力目录分节） | harness agent-lifecycle | `buildMessages`：system = 人设 + 时间 + 能力目录（有内容才加节）；历史/摘要/用户消息按序入 messages |
| **历史持久化**（思考内容不入历史，只存正文；重启可续聊） | harness session persistence | electron-store `chat.history` + `chat.historySummary`；`chat:clear-history` 清空 |

- **请求**：POST `{baseUrl}/chat/completions`（baseUrl 默认 `https://api.deepseek.com`，模型默认 `deepseek-chat`，推理模型填 `deepseek-reasoner`），`stream: true`，AbortController 支持中止
- **单测**：`npm run test:chat`（`scripts/test-chat.js`）——SSE 解析/提示词组装/.env 解析/引擎级重试/无 Key 归一，纯 Node 无 Electron 依赖
- **配置中心「大模型」页签**：Key（password 输入）/地址/模型下拉/人设文本域 + 保存/清空历史按钮；保存值经 `chat:set-config` 落盘，留空则回落 .env；**Key 只在主进程持有**，渲染层页签不显示已存 Key（只显示占位提示）

## 6. 进程间通信（IPC）接口约定

> 三期新增通道（workspace:*/space:*/entry:*/note:*/task:*/cover:*/settings:* 等）随对应里程碑实施时登记于本表；现有通道语义不变。P3-M1 已登记 `workspace:*` 五条；P3-M2 已登记 `workspace:get-data` 与 `space:*`/`entry:*` 七条。

| 通道 | 方向 | 用途 |
|---|---|---|
| `data:get-all` | renderer → main | 拉取全部数据（命令/提醒/设置，旧数据归一化） |
| `reminder:add/update/remove` | renderer → main | 提醒管理 |
| `command:add/update/remove` | renderer → main | 命令管理（含 quick 字段） |
| `clipboard:write` | renderer → main | 写入剪贴板（命令复制） |
| `window:set-ignore-mouse` | renderer → main | 动态切换点击穿透 |
| `window:drag-start/drag-to/drag-end` | renderer → main | 拖动信号（坐标由主进程采集） |
| `window:set-config-open` | renderer → main | 打开/关闭配置中心独立窗口（P3-M1 起右键入口切换为工作台，通道保留待 P3-M7 下线） |
| `workspace:open` | renderer → main | 打开/聚焦正式工作台独立窗口（P3-M1；已打开只恢复聚焦不重复创建） |
| `workspace:get-init` | renderer → main | 工作台初始数据：恢复上次停留页面 lastPage（首次默认 prompts；P3-M7 后按「默认打开界面」设置优先） |
| `workspace:set-page` | renderer → main | 四项导航页切换持久化（lastPage，自名单校验） |
| `workspace:win-control` | renderer → main | 自定义标题栏窗口控制（minimize / maximize-还原 / close，作用于发送方窗口） |
| `workspace:win-state` | main → renderer | 工作台最大化状态同步（切换「最大化/还原」按钮图形） |
| `workspace:get-data` | renderer → main | 工作台拉取空间与条目快照（P3-M2；返回 `{ spaces, entries, defaultSpaceId }`，spaces 按 order 升序） |
| `space:create` | renderer → main | 新建空间（名称 trim/长度≤16/重名拦截；返回最新快照） |
| `space:rename` | renderer → main | 重命名空间（同名校验，排除自身） |
| `space:move` | renderer → main | 空间上移/下移（与相邻交换后统一重写 order） |
| `space:delete` | renderer → main | 删除空间（默认空间/最后一个空间拦截；非空必须 strategy：migrate 迁移到默认空间 / purge 一并删除；迁移不改 updatedAt） |
| `entry:save` | renderer → main | 新建/编辑条目统一入口（id 空即新建；类型白名单 prompt/command；空间存在性/标题≤60/正文≤2000 校验；更新保留 createdAt/coverId） |
| `entry:delete` | renderer → main | 删除条目 |
| `chat:send` | renderer → main | 发送对话消息（主进程 chat.js 引擎流式生成回复） |
| `chat:abort` | renderer → main | 中止未完成的流式请求（面板关闭/重发） |
| `chat:set-config` | renderer → main | 保存「大模型」页签配置（Key/地址/模型/人设） |
| `chat:clear-history` | renderer → main | 清空会话历史与摘要 |
| `app:quit` | renderer → main | 退出应用 |
| `reminder:trigger` | main → renderer | 触发提醒表现（`{ text, preset, type }`；`preset='usage'` 播放使用时长语音） |
| `data:changed` | main → renderer | 数据变更广播（空间/条目/命令变更后同步其它窗口；排除发起者） |
| `chat:chunk` | main → renderer | 流式回复分片（`{delta, kind}`，kind=think 思考/正文） |
| `chat:done` | main → renderer | 本轮回复完成（含 usage 可忽略） |
| `chat:error` | main → renderer | 回复出错（已归一化的用户友好提示） |

## 7. 安全与稳定红线

1. **不执行任何用户命令**（无 `child_process`，后续再议）
2. `contextIsolation: true` + `nodeIntegration: false`，渲染层只通过 preload 白名单接口访问能力
3. 所有用户输入（提醒文本/命令内容）渲染时使用 `textContent`，禁止 `innerHTML` 拼接，防注入
4. electron-store 读写加 try/catch，数据损坏时回退默认值而非崩溃
5. **API Key 安全**：Key 只存于主进程内存/electron-store/.env，渲染层不持有真实 Key；`.env` 被 .gitignore 与 files 白名单双重排除；请求只在主进程发起（chat.js），渲染层不直连外部 API
6. 每次修改后必须 `npm start` 实测通过才算完成该步骤
