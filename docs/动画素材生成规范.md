# 桌宠动画素材生成规范（AI 生成用）

> 目的：用 AI 生成桌宠动画素材，替换当前 emoji（🐱）渲染方式。
> 本文档给出素材的格式、尺寸、锚点、风格、命名规范与**可直接复制给 AI 的提示词**，以及生成后的落地集成与验收标准。
> 关联代码：index.html（#pet）、styles.css（.anim-* 状态机）、renderer.js（setPetState）
> 日期：2026-08-19

---

## 1. 现状：动画状态机与素材对照

当前宠物本体是 128px 的 emoji 字符，由 CSS transform 动画驱动。状态机共 3 态、5 个动作，素材必须一一对应：

| 状态 | 类名 | 触发时机 | 当前 CSS 实现 | 素材时长要求（硬约束） |
|---|---|---|---|---|
| 待机 | `anim-idle` | 默认；任何互动结束 1.2s 后自动回归 | breathe 5s 呼吸（scale 1→1.05 + 上移 3px） | **4-6 秒无缝循环** |
| 互动·跳 | `anim-jump` | 左键单击，随机 1/3 概率 | jump 0.6s×2，跳起 34px | **1.2 秒完整循环（跳两下）** |
| 互动·转 | `anim-spin` | 左键单击，随机 1/3 概率 | spin 1.1s 顺时针转 360° | **1.2 秒完整循环（转一整圈）** |
| 互动·摇 | `anim-wiggle` | 左键单击，随机 1/3 概率 | wiggle 0.3s×4，左右 ±10° | **1.2 秒完整循环（左右摇摆）** |
| 提醒 | `anim-remind` | 提醒到点时（持续到用户处理） | bounce 0.5s 无限弹跳（上 12px） | **0.5-1 秒无缝循环** |
| 拖拽（可选加分） | — | 按住左键拖动时 | 无（沿用当前状态） | 静态悬空立绘，或 1 秒内轻微挣扎循环 |

**时长对齐原理**：代码中互动动画有 1.2 秒兜底定时器（`actionTimer`），1.2s 后自动切回待机。三个互动素材统一做成 **1.2 秒完整循环**，即可与现有逻辑零改动对齐——素材播完一循环恰好被切回 idle，不会出现"动作做一半被切走"的割裂感。

## 2. 格式规范（硬约束）

| 项目 | 规范 | 原因 |
|---|---|---|
| 首选格式 | **WebP 动图**（有损/无损均可） | Electron 内置 Chromium 原生支持；全彩 + 8bit alpha + 体积最小 |
| 次选格式 | APNG | 全彩透明，但体积约为 WebP 的 2-3 倍 |
| 不推荐 | GIF | 仅 256 色、无半透明，边缘必有锯齿白边 |
| 静态立绘 | PNG（RGBA） | 用于 drag 状态或兜底方案 |
| 帧率 | **24 fps**（不超过 30） | 透明悬浮窗常驻合成，帧率过高徒增解码开销（v2.4 性能约定） |
| 分辨率 | **512×512**（4x 超采样，256×256 为最低可接受） | 窗口内逻辑显示尺寸约 160px，4x 保证高分屏清晰 |
| 单文件大小 | **≤ 1MB**（目标 300-500KB） | 避免加载卡顿与内存占用 |
| 全部素材合计 | ≤ 3MB | 打包体积与加载时长控制 |
| 背景 | **必须全透明（alpha=0）**，严禁白底/纯色底 | 悬浮窗本身就是透明窗口，素材背景不透明会显示矩形色块 |

## 3. 画布与锚点规范

- 画布 **512×512**，正方形。
- 角色占画布高度的 **80%-90%**（脚底到头顶约 410-460px），不要太小也不要顶边。
- **锚点 = 角色脚底居中**：水平中线 x=256px，脚底距画布底边 **16-32px**。
  - 代码中宠物定位在窗口底部居中（`bottom: 16px` + `translateX(-50%)`），脚底贴画布底边能保证落地位置正确；角色脚底悬空会导致宠物"浮在空中"。
- 阴影处理（二选一）：
  - **推荐：阴影画进素材**——角色脚下放一个深灰（#000、15-20% 不透明度）椭圆投影，随角色动作轻微缩放/淡入淡出。落地后代码会删除 `filter: drop-shadow`，避免滤镜每帧重光栅化（这正是 v2.4 性能优化的目标）。
  - 备选：素材不带阴影，代码保留现有 drop-shadow——但素材边缘必须干净无杂色毛边。

## 4. 角色设定（风格一致性）

- **默认角色**：橙色短毛小猫（呼应应用图标"猫猫头"）。
- **画风**：扁平圆润可爱风（flat & cute cartoon），粗描边（2-4px 深棕/深灰描边），配色明亮温暖，形状圆润无尖角。
- 备选画风：16bit 像素风——一旦选择，**所有状态必须同一画风**，不得混用。
- **一致性要求（最重要）**：同一只猫的体型、配色、脸型、花纹在所有状态素材中完全一致。生成多个状态时，每个提示词都要**完整重复角色描述**；如有角色设定图，务必作为参考图传入（img2img / reference image）。
- 各状态表情规范：

| 状态 | 表情 |
|---|---|
| idle | 放松、微笑、偶尔眨眼 |
| jump | 开心、睁大眼睛 |
| spin | 兴奋、咧嘴笑 |
| wiggle | 俏皮、单眼眨（wink） |
| remind | 着急、嘴巴张圆、招手呼唤 |

## 5. 各状态生成规范与提示词模板

### 通用提示词前缀（每个状态都要带上）

```
512x512, transparent background with alpha channel, flat cute cartoon style,
orange short-haired kitten mascot with big round eyes and small white belly,
thick dark brown outline, soft rounded shapes, consistent character design,
seamless looping animation, 24 fps, no text, no watermark
```

### 5.1 idle 待机（4-6 秒无缝循环）

动作：站立呼吸——胸腔起伏、身体轻微上下浮动（幅度约画布高度 2-3%）、耳朵偶尔轻抖、尾巴缓慢摆动。

```
[通用前缀], the kitten standing and breathing gently, chest rising and falling,
slight body bob, ears twitching occasionally, tail swaying slowly, calm happy
expression, 5 second seamless loop
```

### 5.2 jump 跳（1.2 秒完整循环，跳两下）

动作：连续小跳两次——起跳身体拉长、四肢舒展，落地膝盖缓冲，两次节奏相同。

```
[通用前缀], the kitten jumping up and down twice excitedly in a row, full body
stretch in the air, landing softly with bent knees, joyful wide-eyed expression,
1.2 second loop
```

### 5.3 spin 转（1.2 秒完整循环，转一整圈）

动作：顺时针原地旋转 360°，前爪张开保持平衡，旋转中保持可爱表情。

```
[通用前缀], the kitten spinning 360 degrees clockwise once, front paws stretched
out for balance, joyful playful energy, excited smile, 1.2 second loop
```

### 5.4 wiggle 摇（1.2 秒完整循环，左右摇摆）

动作：上半身左右摇摆约 4 次（幅度约 10°），尾巴反向摆动，单眼眨。

```
[通用前缀], the kitten wiggling its upper body side to side playfully about four
times, tail swinging in opposite direction, winking with one eye, cute mischievous
smile, 1.2 second loop
```

### 5.5 remind 提醒（0.5-1 秒无缝循环）

动作：原地小跳 + 举爪招手，身体前倾，表情急切。

```
[通用前缀], the kitten bouncing up and down energetically while waving one front
paw to get attention, leaning forward, urgent calling expression with round open
mouth, 0.8 second seamless loop
```

### 5.6 drag 拖拽（可选，静态或 1 秒循环）

动作：四肢自然下垂的"被拎起"悬空姿势，可加轻微摆动。

```
[通用前缀], the kitten hanging in the air being lifted by the scruff, four paws
dangling loosely, slightly dizzy expression, gentle swinging, 1 second seamless loop
```

## 6. AI 生成常见问题与处理

| 问题 | 处理 |
|---|---|
| 生成结果带背景 | 用抠图工具（remove.bg 等）去底，边缘 feather 1-2px 防毛边 |
| 循环不无缝（首尾帧跳变） | 提示词强调 seamless loop；生成后用播放器逐帧检查首尾帧；不达标则重生成或选素材内最长的一段平稳区间裁剪 |
| 多状态角色不一致 | 用同一角色设定图做参考图传入；把"完整角色描述"写进每个提示词；同批生成（相同 seed 更佳） |
| AI 输出是 MP4 视频 | 用 ffmpeg 转 WebP：`ffmpeg -i out.mp4 -vf "scale=512:512" -loop 0 -q:v 75 pet-idle.webp`（-q:v 75 为质量参数，体积超标则降到 60） |
| 生成分辨率不标准 | 统一缩放/裁切到 512×512 并重新核对脚底锚点 |

## 7. 命名与存放

```
assets/pet/
├── pet-idle.webp       # 待机（必选）
├── pet-jump.webp       # 互动·跳（必选）
├── pet-spin.webp       # 互动·转（必选）
├── pet-wiggle.webp     # 互动·摇（必选）
├── pet-remind.webp     # 提醒（必选）
├── pet-drag.webp       # 拖拽（可选）
└── pet-static.png      # 静态立绘（备选方案 B 用）
```

命名规则：`pet-{状态}.{ext}` 小写连字符；若用 APNG/GIF 则对应 `.apng`/`.gif` 后缀（同目录只允许一种格式并存一套）。

## 8. 落地集成方式（生成完成后）

改动很小，状态机逻辑完全不动：

1. **index.html**：`<div id="pet">🐱</div>` 的 emoji 换成 `<img src="assets/pet/pet-idle.webp">`（保留 `class="anim-idle interactive"` 与 title）。
2. **renderer.js**：`setPetState` 中按状态切换 `img.src`（idle→pet-idle、随机 action→三者其一、remind→pet-remind）；`actionTimer` 1.2s 兜底保持不变（素材 1.2s 循环天然对齐）。
3. **styles.css**：`#pet` 的 `font-size: 128px` 改为 `width: 160px; height: 160px`；素材自带阴影则删除 `filter: drop-shadow(...)`；删除不再使用的 keyframes（breathe/jump/spin/wiggle/bounce）。
4. **package.json**：`files` 白名单加 `assets/pet` 目录，重新打包校验。

**性能约定（不可违反）**：素材播放是常驻解码开销（透明窗口持续合成），帧率 24fps、单文件 ≤1MB 是硬约束；集成后需实测 CPU/GPU 占用不高于当前 emoji 版本（任务管理器对比）。

## 9. 验收清单

- [ ] 全部 5 个必选状态素材就位（+ 可选 drag）
- [ ] 每个素材：512×512、24fps、≤1MB、背景全透明（在深色背景下预览无白边/色块）
- [ ] 循环无缝（首尾帧衔接自然）
- [ ] 脚底锚点居中、距画布底边 16-32px，集成后宠物不悬空不穿地
- [ ] 角色一致性：五状态是同一只猫（体型/配色/花纹）
- [ ] 命名符合 `pet-{状态}.webp` 规范
- [ ] 集成后行为验收：单击随机触发三动作、1.2s 后回待机；提醒循环流畅；双击/右键/拖动不受影响
- [ ] 性能验收：任务管理器对比，待机 CPU/GPU 占用不高于 emoji 版本

## 10. 风险与备选方案

| 方案 | 说明 | 适用场景 |
|---|---|---|
| **方案 A（本文档默认）**：AI 生成 5 个 WebP 动图 | 动作最生动，替换 emoji 后桌宠"活了" | 素材质量达标时 |
| **方案 B：仅生成静态立绘 PNG** | 保留现有 CSS transform 动画（breathe/jump/spin/wiggle/bounce）驱动立绘，只换"脸"不换"动" | 动图生成质量不达标时的最小改动兜底 |
| **方案 C：Live2D** | 骨骼动画表现力最强，但需引入引擎与模型文件，工作量翻倍 | 二期按需评估，不在本期范围 |
