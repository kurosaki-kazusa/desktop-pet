## 一、技术选型类

### Q1. 项目结构形式
- **A. 最小化三文件结构（🌟 推荐）**：仅 `package.json` + `main.js` + `index.html`，结构简单清晰，维护成本低
- B. 使用 electron-vite / forge 脚手架：工程化完善，但目录复杂、依赖多
- C. 主进程/渲染进程严格分离 + preload 桥接的完整架构：规范但对小项目过度设计

### Q2. 渲染层（宠物界面）技术方案
- **A. 原生 HTML/CSS/JS（🌟 推荐）**：零依赖、零构建，实现最简单，代码直观易改
- B. Vue 3：组件化管理列表方便，但引入构建链，依赖增加
- C. React：同 B，JSX 门槛更高

### Q3. 数据持久化方案
提醒事项和命令记录数据存在哪里？

- **A. electron-store 库（🌟 推荐）**：一行代码完成 JSON 读写与持久化，API 极简，稳定可靠
- B. Node.js 手动读写 JSON 文件：可控性强，但需自己处理路径、序列化、错误兜底
- C. localStorage：最简单，但 Electron 窗口生命周期下有数据丢失风险

### Q4. 提醒触发方式
到点提醒以什么形式呈现？

- **A. 应用内悬浮气泡 + 提示音（🌟 推荐）**：宠物旁弹出气泡 + 播放音效，效果直观且完全可控
- B. Electron 系统通知（`Notification` API）：更"原生"，但通知可能被系统收纳/静音
- C. A + B 组合：体验最完整，实现量增加

### Q5. 宠物形象与动画素材
- **A. 像素风 GIF / 序列帧（🌟 推荐）**：实现最简单，风格讨喜，素材可用 AI 生图工具生成
- B. AI 生成静态图 + CSS 微动画（呼吸/浮动效果）：效果柔和，但"活"的感觉弱于帧动画
- C. Live2D：表现力天花板，但 SDK 集成复杂，成本远超收益

## 二、需求细节类

### Q6. 定时提醒的数据模型
- **A. 定点提醒 + 周期提醒两种类型（🌟 推荐）**：定点 = 指定时刻触发；周期 = 每 N 分钟触发（喝水/护眼复用此类型），模型清晰且覆盖一期需求
- B. 仅定点提醒：护眼/时长提醒靠手动添加多条定点提醒实现，最简但体验差
- C. 定点 + 周期 + 每日重复：功能最全，但重复规则的时间计算复杂度高

### Q7. 使用时长提醒的判定方式
- **A. 应用启动后计时（🌟 推荐）**：从宠物启动起累计运行时长，到阈值提醒休息；实现简单、逻辑自洽
- B. 统计全电脑使用时长（键鼠活动检测）：更真实，但需要系统级 API，严重超纲
- C. 不做时长统计，退化为固定间隔提醒：最简，但失去"使用电脑时长"的语义

### Q8. 护眼/使用时长提醒的预置策略
这两类提醒由谁创建？

- **A. 系统预置默认值，用户可修改间隔（🌟 推荐）**：开箱即用（如默认每 45 分钟护眼、每 60 分钟时长提醒），同时保留自定义空间
- B. 完全由用户手动创建：最灵活，但新用户不知道该建什么
- C. 系统预置且不可修改：实现最简，但灵活性差

### Q9. 命令记录器的管理操作
常用命令如何维护？

- **A. 在气泡内提供表单：新增 / 编辑 / 删除（🌟 推荐）**：闭环完整，操作都在气泡内完成
- B. 仅支持新增和删除，不支持编辑：实现略简，改错只能删了重建
- C. 从本地 txt/md 文件导入命令：省去表单开发，但依赖用户维护文件，体验割裂

### Q10. 提醒管理的入口位置
添加/编辑/删除提醒的界面放在哪里？

- **A. 会话气泡内，与命令记录器并列（如 Tab 切换）（🌟 推荐）**：所有功能集中在右键气泡，入口统一
- B. 左键双击打开的功能面板中：气泡保持轻量，但提醒管理入口较深
- C. 右键气泡中再嵌套二级菜单：层次多，交互复杂

### Q11. 鼠标左键单击/双击的功能分配
> 交互框架已确定：日常状态桌宠以呼吸动画活动；鼠标左键点击触发交互动作（区分单击/双击）；鼠标右键点击弹出会话气泡（一期含常用命令记录器，搜索为二期扩展）。以下为剩余待定点：

- **A. 单击 = 宠物交互动作，双击 = 打开功能面板（🌟 推荐）**：单击轻量有趣，双击进入重功能，符合直觉
- B. 单击 = 打开功能面板，双击 = 宠物交互动作：功能入口更直接，但易误触、削弱宠物趣味
- C. 单击 = 交互动作，双击 = 切换宠物表情/皮肤：纯趣味向，但需另设功能面板入口

### Q12. 宠物交互动作的形式（左键点击反馈）
- **A. 多套预设动作随机播放（如摇摆/跳跃/转圈）（🌟 推荐）**：实现简单，有惊喜感
- B. 单一固定动作：实现最简
- C. 点击不同部位（头/身体）有不同反应：趣味强，但命中判定实现成本高

### Q13. 提醒触发时的表现形式
- **A. 宠物切换提醒动画 + 提示音 + 气泡显示提醒内容（🌟 推荐）**：视觉 + 听觉 + 内容三位一体，效果完整
- B. 仅气泡 + 提示音，宠物动画不变：实现最简
- C. 仅提醒动画 + 提示音，无内容气泡：提醒内容传达弱

### Q14. 会话气泡的界面形态
- **A. 气泡样式面板（带指向宠物的小箭头），一期内含命令记录器，二期可扩展 Tab（🌟 推荐）**：贴合"会话气泡"设定，且为二期搜索功能预留了 Tab 结构
- B. 普通悬浮面板（无气泡造型）：实现最简单，但氛围感弱
- C. 极简气泡只显示命令列表，管理功能另开窗口：层次多，复杂度高

### Q15. 宠物拖动与位置
- **A. 支持拖动移动位置，并记住关闭前的位置（🌟 推荐）**：桌宠的基础预期功能
- B. 支持拖动，但不记忆位置（每次启动重置）：实现略简
- C. 固定位置，不支持拖动：最简，但体验差

### Q16. 会话气泡的关闭方式
- **A. 点击桌面空白处或气泡关闭按钮（🌟 推荐）**：自然直观
- B. 仅关闭按钮：实现最简单
- C. 自动延时隐藏 + 关闭按钮：更智能，但可能在用户操作中途消失

### Q17. 提示音设计
- **A. 单一统一提示音（🌟 推荐）**：简单可靠
- B. 不同提醒类型不同音效（定点/护眼/时长）：区分度好，但需更多音效素材
- C. 无音效，仅视觉提醒：安静，但提醒容易被错过

### Q18. 提醒错过补偿策略
提醒触发时用户没看到（如电脑锁屏），如何处理？

- **A. 不做补偿，错过即错过（🌟 推荐）**：不引入复杂状态，保持实现简洁
- B. 未确认的提醒保留在"未处理"列表中：需要额外的确认/状态管理
- C. 下次打开面板时补显示错过的提醒：体验好但逻辑分支多
